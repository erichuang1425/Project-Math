# The method — passive read + active recall

Adapted from loom-notes `skill/reference/method.md` (MIT). The pedagogy is
unchanged; the devices are Project-Math blocks.

The whole point: a learner should be able to **read** the notes like exposition,
and also **do** them like a worksheet. Get the ratio right and learning feels
effortless; get it wrong and you have either a transcript (no thinking) or a
blank worksheet (no scaffold).

## The 70/30 rule

Roughly **70% readable, 30% to fill.** Put the gaps at the _high-value thinking
points_, not everywhere.

**Leave readable (passive) — use `concept`, `intuition`, `latex`, `graph`, `workedExample`:**

- Motivation and intuition.
- Theorem / definition statements — in full. The learner should always know the claim.
- The shape of a worked example (the named steps) and any standard input that isn't the point.

**Blank out (active) — use `fillIn` `blank` runs:**

- The _key step_ of a derivation — the one move that makes it work.
- A _defining clause_ of a definition (state the term + frame, blank the condition).
- The _punchline_: the answer, the constant, the limit value.
- A _constraint_ that is easy to forget (e.g. `h \ne 0` before the limit).

## Find the spine first

Before writing, name the ONE organizing idea and build the lesson around it. A
chapter reorganized around its spine teaches far better than a faithful
transcript. Spines: a dictionary (algebra ↔ geometry), an engine list (which
rule for which structure), a single theorem the rest orbits, a mirrored pair (an
idea and its dual). Keep the source's order only if it _is_ the best shape.

## Per-lesson rhythm (maps onto the app micro-flow)

`intuition` (thesis / why it matters) → `concept` + `latex` (state the result,
read) → `graph` (anchor attention) → `workedExample` (Calculate) → `fillIn`
recall pause (the active layer, before the quiz) → `quiz` (Answer) → `summary`
(Summarize). This is the Observe → Predict → Calculate → Compare → Answer →
Summarize flow from `docs/learning-design.md`.

## Tone

Warm, concrete, lean. Prefer the source's best concrete example over an abstract
one. State honestly; don't inflate. Keep learner-facing sentences short and
literal (see the autism-aware lesson style in `docs/learning-design.md`).
